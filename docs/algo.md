## 1. 診斷計數器設計架構

```python
stats_counter = {
    'total': 0,           # 總掃描窗口數
    'monotonic_fail': 0,  # 階段 1: 電流非單調 → 跳過
    'r2_pre_fail': 0,     # 階段 2: Cheung I 的 R² < 0.8 → 跳過
    'constraint_fail': 0, # 階段 3: n 或 R² 超出約束 → 跳過
    'r2_final_fail': 0,   # 階段 4: Cheung II 的 R² 不足 → 跳過
    'rs_mismatch': 0,     # 階段 5: Rs 不一致 → 跳過
    'success': 0          # ✅ 通過所有階段
}
```

### 設計理念：五階段漏斗式過濾機制

```
                    總窗口數 (total)
                         │
                         ▼
              ┌──────────────────────┐
              │ 階段 1: 單調性檢查    │ ← 物理基礎：正向偏壓電流應單調增長
              │ monotonic_fail       │
              └──────────┬───────────┘
                         │ 通過
                         ▼
              ┌──────────────────────┐
              │ 階段 2: Cheung I 預篩 │ ← 快速排除：R² < 0.8 直接跳過
              │ r2_pre_fail          │
              └──────────┬───────────┘
                         │ 通過
                         ▼
              ┌──────────────────────┐
              │ 階段 3: 物理約束檢查  │ ← 核心：n 範圍、R²閾值
              │ constraint_fail      │
              └──────────┬───────────┘
                         │ 通過
                         ▼
              ┌──────────────────────┐
              │ 階段 4: Cheung II 驗證│ ← 雙重驗證：H(I) 線性度
              │ r2_final_fail        │
              └──────────┬───────────┘
                         │ 通過
                         ▼
              ┌──────────────────────┐
              │ 階段 5: Rs 一致性檢查 │ ← 自洽性：兩種方法提取的 Rs 應接近
              │ rs_mismatch          │
              └──────────┬───────────┘
                         │ 通過
                         ▼
                    ✅ success!
```

### 五階段設計依據

| 階段 | 目的 | 計算成本 | 排除比例 |
|-----|------|---------|---------|
| 1. 單調性 | 物理合理性驗證 | 低 | ~30% |
| 2. R²預篩 | 快速排除不良窗口 | 低 | ~20% |
| 3. 約束檢查 | 核心物理約束 | 中 | ~30% |
| 4. Cheung II | 雙重驗證 | 中 | ~10% |
| 5. Rs 一致性 | 自洽性檢查 | 低 | ~5% |

**設計優勢**：
- ✅ **早期排除機制**：優先執行低計算成本檢查，避免不必要的運算資源浪費
- ✅ **診斷資訊完整**：失敗時可精確定位問題階段，便於參數調整
- ✅ **物理嚴謹性**：多重驗證機制確保擬合結果可靠性

## 2. 滑動窗口迭代邏輯

```python
window = self.config.window_size  # 例如：25 點
step = self.config.step_size      # 例如：3 點

for start_idx in range(0, len(bias_proc) - window + 1, step):
    end_idx = start_idx + window
    stats_counter['total'] += 1  # ← 每個窗口計數 +1

    I_win = I_proc[start_idx:end_idx]
    V_win = bias_proc[start_idx:end_idx]
    y_win = dV_dlnI[start_idx:end_idx]

    # ... 五階段檢查 ...

    if 所有檢查通過:
        stats_counter['success'] += 1  # ← 通過才計數
```

### 滑動過程視覺化

```
假設：bias_proc 長度 = 100 點，window=25, step=3

窗口 1: [0:25]   → 檢查 → 失敗 → monotonic_fail += 1
窗口 2: [3:28]   → 檢查 → 失敗 → r2_pre_fail += 1
窗口 3: [6:31]   → 檢查 → 成功 → success += 1  ⭐
窗口 4: [9:34]   → 檢查 → 失敗 → constraint_fail += 1
...
窗口 32: [93:118] → 檢查 → 失敗 → rs_mismatch += 1

總窗口數 = (100 - 25) // 3 + 1 = 26 個窗口
```

### 總計數與成功數差異說明

```
total = 72   ← 掃描了 72 個窗口
success = 0  ← 無一通過全部五階段檢查

可能原因：
• 所有窗口的 n 值均超出約束範圍 (n > 5.0)
• Cheung II 的 R² 均未達標
• Rs 一致性檢查失敗
```

**此即「多階段篩選失敗。通過：0/72」之具體含義**

## 3. `_compute_score()` 函數功能說明

```python
def _compute_score(self, r2: float, I_range: Tuple[float, float],
                   residuals: np.ndarray) -> float:
    """
    綜合評分：選擇「最佳」窗口

    評分組成:
    - R² 權重 60%: 線性度最重要
    - 電流跨度 30%: 覆蓋範圍越寬越好
    - 平滑度 10%: 殘差越小越好
    """
    score_r2 = r2 * 0.6

    log_span = np.log10(I_range[1] / (I_range[0] + 1e-20))
    score_range = min(log_span / 2.0, 1.0) * 0.3

    smoothness = 1.0 / (1.0 + np.std(residuals) * 1e3)
    score_smooth = smoothness * 0.1

    return score_r2 + score_range + score_smooth
```

### 評分機制必要性

**應用情境**：多個窗口均通過五階段檢查時，如何選擇最佳結果？

```
窗口 A: R²=0.96, 電流跨度=1 decade, 殘差小 → score=0.85
窗口 B: R²=0.92, 電流跨度=2 decades, 殘差中 → score=0.82
窗口 C: R²=0.98, 電流跨度=0.5 decade, 殘差大 → score=0.79

選擇：窗口 A (最高分)
```

### 評分公式詳細說明

```python
# 1. R² 分數 (60%)
score_r2 = r2 * 0.6
# R²=0.95 → 0.57 分

# 2. 電流跨度分數 (30%)
log_span = np.log10(I_max / I_min)  # 例如：2 decades
score_range = min(log_span / 2.0, 1.0) * 0.3
# 跨度 2 decades → 1.0 * 0.3 = 0.3 分
# 跨度 1 decade → 0.5 * 0.3 = 0.15 分

# 3. 平滑度分數 (10%)
smoothness = 1.0 / (1.0 + std(residuals) * 1000)
score_smooth = smoothness * 0.1
# 殘差小 → 接近 0.1 分
# 殘差大 → 接近 0 分

# 總分 = 0.57 + 0.3 + 0.1 = 0.97 (滿分)
```

### 物理意義對照表

| 評分類別 | 物理意義 | 重要性說明 |
|-------|---------|-----------|
| **R² (60%)** | 線性度 | Cheung 方法核心假設：dV/d(lnI) vs I 應呈線性關係 |
| **電流跨度 (30%)** | 數據覆蓋範圍 | 跨度过窄 → 結果對噪聲敏感度增加 |
| **平滑度 (10%)** | 擬合品質 | 殘差過大 → 可能存在未建模物理效應 |

## 5. L6 嚴格約束參數優勢分析

| 約束條件 | 寬鬆設定 (n_max=15) | 嚴格設定 (n_max=5) | 影響評估 |
|-----|----------------|---------------|------|
| **成功率** | 100% | 50% | 嚴格約束排除不可靠數據 |
| **n 平均值** | 9.43 | 2.36 | 嚴格約束排除高 n 異常值 |
| **ΦB 範圍** | 0.08-0.14 eV | 0.37 eV | 嚴格約束結果更集中 |
| **物理意義** | 存疑 (n~10) | 合理 (n~2-3) | 嚴格約束更符合熱電子發射模型 |

**關鍵洞察**：
> **高成功率 ≠ 優質結果**
>
> 寬鬆約束雖使所有像素均「擬合成功」，但 n~10 表明可能非純熱電子發射主導
>
> 嚴格約束雖成功率僅 50%，但通過之像素結果物理意義明確

## 6. 總結

| 組件 | 功能 | 重要性 |
|-----|------|-----------|
| **五階段計數器** | 診斷失敗原因 | 精確定位問題階段，便於參數調整 |
| **滑動窗口機制** | 系統性掃描全偏壓區 | 避免手動選擇之主觀性 |
| **評分函數** | 從多個合格窗口選擇最佳結果 | 確保結果最優化而非隨機選擇 |
| **嚴格約束** | 排除物理上不合理的擬合 | 保證結果可靠性 |
